## Overview

This project studies a nonlinear discrete-time model of price and blockchain-effort dynamics between two competing cross-border e-commerce sales channels (SC1: manufacturer-direct, SC2: platform-resale), adapted from the ME-mode model in Wang, Chai & Wen (*Entropy*, 2025) [1]. The state vector is

```
x = [p1; p2; b1; b2]
```

where `p1, p2` are retail prices and `b1, b2` are blockchain maintenance efforts for SC1 and SC2 respectively. Boundedly rational players adjust each variable in the direction of their current marginal profit, producing a nonlinear map `x(t+1) = f(x(t), u(t))`.

The group added two elements not defined in the source paper:
- **Control input `u`**: an additive price correction applied directly to the SC2 price update.
- **Measured output `y = [p1; p2]`**: only the two retail prices are assumed directly observable; blockchain effort levels are internal/unmeasured.

## Data Flow

All numerical results are shared between scripts via `system_model.mat`, generated by `system_model.m` and appended to by `stability_feedback.m`. This avoids retyping/hardcoding matrices between scripts and keeps every part working off the same equilibrium and linearisation.

`system_model.mat` contains:
- `A, B, C, D` — linearised state-space matrices (baseline speed ω = 0.01)
- `A_sym, B_sym` — symbolic Jacobians, used to relinearise at other adjustment speeds
- `x_star, u_star, p1_star, p2_star, b1_star, b2_star, q1_star, q2_star` — interior equilibrium
- `F` — numeric function handle for the nonlinear update `f(p1,p2,b1,b2,u,ω1,ω2,μ1,μ2)`
- `K, closed_loop_eig` — LQR state-feedback gain and resulting closed-loop eigenvalues

> `system_model.mat` is a generated file, committed for reproducibility. To regenerate it from scratch, rerun `system_model.m` then `stability_feedback.m`.

## Summary of Results

**System model & linearisation:** a positive interior equilibrium was found and verified (`||f(x*) - x*|| < 1e-8`, all states/demands positive).

**Stability & control:** the open-loop linearised system is stable (all eigenvalues of `A` inside the unit circle); the system is controllable via the single input `u` acting on `p2`; an LQR gain `K` was designed and confirmed to keep the closed-loop system stable.

**Observability & observer:** the system is fully observable from price measurements alone (`rank(obsv(A,C)) = 4`); a Luenberger observer was designed with poles faster than the closed-loop control poles, confirming the state estimate converges before the controller needs to trust it.

**Nonlinear behaviour:** a bifurcation scan over the adjustment speed `ω` identified stable (ω ≈ 0.01–0.055), unstable/oscillatory (ω ≈ 0.06–0.065), and chaotic (ω ≈ 0.07–0.075) regimes. In the unstable regime, the baseline controller (tuned at ω = 0.01) failed to stabilise the system, since it no longer matched the local dynamics; relinearising `A`, `B` and redesigning `K` at the unstable regime's speed successfully stabilised it. A full observer-based control pipeline — controller acting only on the estimated state, estimated from price measurements only — was shown to stabilise all four states (including the unmeasured `b1, b2`) from the unstable regime back to equilibrium.
